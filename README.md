## Installation

Run all commands from the repository root.

Use a Python version compatible with the project's `requires-python` setting in `pyproject.toml`.

### macOS / Linux

Create a project-local virtual environment:

```bash
python3 -m venv .venv
```

Install the package and development dependencies inside it:

```bash
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -e ".[dev]"
```

Verify the interpreter and environment:

```bash
./.venv/bin/python -c "import sys; print('Interpreter:', sys.executable); print('Virtual environment:', sys.prefix != sys.base_prefix)"
```

The interpreter path should point inside this repository's `.venv`, and the virtual-environment check should print `True`.

### Windows PowerShell

Create and install into the project-local environment:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Verify it:

```powershell
.\.venv\Scripts\python.exe -c "import sys; print('Interpreter:', sys.executable); print('Virtual environment:', sys.prefix != sys.base_prefix)"
```

### Optional activation

Activation makes shorter commands available in the current terminal.

macOS / Linux:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

After activation, use `python -m pip`, `python -m pytest`, and `python -m cluster_representation`.

The explicit interpreter commands below work without activation. No global installation, `sudo pip`, or `pip install --user` is needed.

Keep `.venv/` in `.gitignore`. Recreate the environment on each machine rather than committing or copying it.

## Run the workflow

From the repository root, run the complete configured pipeline.

macOS / Linux:

```bash
./.venv/bin/python -m cluster_representation --config config/default.yml
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m cluster_representation --config config/default.yml
```

Run an individual stage after its prerequisites have been saved.

macOS / Linux:

```bash
./.venv/bin/python -m cluster_representation \
  --config config/default.yml \
  --step generate_dataset
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m cluster_representation --config config/default.yml --step generate_dataset
```

Supported stages:

- `generate_dataset`
- `split_dataset`
- `fit_preprocessor`
- `train_model`
- `build_prototypes`
- `transform_test`
- `evaluate`

Each stage validates its prerequisite artifacts and reports missing or incompatible inputs.
`transform_test` processes every indicator generated by the configured
`nonconsent` range. Its scenario-specific outputs are saved under
`models/<model>/transformed/<scenario>/` or
`models/<model>/k_<selected-k>/transformed/<scenario>/` when cluster search is enabled;
evaluation reuses those saved outputs.

Existing artifacts are not overwritten unless `output.overwrite: true` is configured. Use a new `output.run_name` for a separate experiment.

All application implementation lives in `src/cluster_representation/`. The CLI and notebooks call the same stage functions.

## Constrained K-means cluster search

The K-means model configuration can use `cluster_search` to fit a supplied list
of cluster counts. For example:

```yaml
name: constrained_kmeans
parameters:
  random_state: 12345
  max_iter: 300
  n_init: 10
cluster_search:
  enabled: true
  candidates: [5, 6, 7, 8, 9, 10]
  selected_n_clusters: 5
constraints:
  type: minimum_cluster_size
  min_cluster_size: 100
```

Candidate counts must be unique positive integers; nonconsecutive values are
valid. Candidates that do not satisfy `K * min_cluster_size <= n_train` are
recorded as skipped in the comparison report. Each feasible candidate is fitted
independently on the same saved training split and fitted preprocessing. Scores
are calculated using training data only, and the same deterministic sample is
used for silhouette comparisons. Each candidate's model, fitted training
assignments, metadata, and training-median prototypes are saved in their own
`models/constrained_kmeans/k_<K>/` directory.

`selected_n_clusters` may be a positive candidate integer or `auto`. An
integer always selects that candidate, regardless of its relative metric
scores. `auto` requires enabled search and ranks eligible candidates by the
average ranks of silhouette (descending), Davies–Bouldin (ascending), and
Calinski–Harabasz (descending). Ties in metric values receive average ranks;
the lowest mean rank wins, with smaller requested `k` breaking a score tie.
Training failures, unavailable/non-finite metrics, and hard-constraint
violations are excluded and reported. Automatic selection fails explicitly if
no candidate is eligible.

The resolved candidate is used for test assignment and replacement; changing
the selected candidate does not refit candidate models. If a fixed candidate
was skipped or failed, training stops with an explicit error. The training
notebook displays the saved comparison table, including automatic selection
scores and the chosen candidate, and the package-generated score plot. Legacy
single-model configurations with `parameters.n_clusters` and no
`cluster_search` remain supported.

The evaluation notebook writes `metrics/combined_evaluation.csv` and
`metrics/combined_evaluation.parquet`. Search runs include one row for each
successfully trained candidate and configured non-consent scenario. Training
cluster metrics are reused from the candidate comparison, and test replacement
errors are calculated from each saved candidate model and prototype without
refitting. The returned notebook table uses readable labels and displays
unavailable values as `N/A`; the exported files retain machine-readable column
names and null metric values.

The evaluation stage writes `tables/overall_comparison.md` with one row per
executed method/model configuration and configured non-consent scenario. AP
and F1 are shown as unavailable because they are not calculated by this
clustering workflow. The table's time column is model fitting time in seconds.
Its `N MAE` and MAPE columns use replaced rows only; raw MAE is retained in
structured metrics but omitted from this compact comparison. N MAE is the
equal-weight mean of per-feature MAEs divided by population standard deviations
from the imputed original-unit training features; constant features are
excluded. MAPE excludes cells whose original value is zero. The detailed
scenario results retain the all-test-row MAE and `per_feature_mae` outputs for
compatibility. Shared scales and their imputation policy are saved in
`preprocessing/training_feature_scales.json`.

The same evaluation stage writes `tables/feature_evaluation.md`, with one row
per executed method/model configuration, NC scenario and configured feature.
It reports replaced-row count, per-feature MAE in original units, MAPE over
nonzero original values, N MAE (feature MAE divided by shared training SD),
training SD and MAPE valid/excluded cell counts. Lower MAE, MAPE and N MAE are
better; N MAE is a training-standard-deviation ratio, not a percentage.
Per-feature values and statuses are calculated and saved in each scenario's
structured results, not recomputed by the Markdown renderer. The reports can
be regenerated from saved metrics with
`reporting.export_saved_evaluation_reports(config)` without retraining. For
older results that lack per-feature metrics, the feature table shows em dashes
and explains that the saved results predate per-feature evaluation.

The evaluation stage also writes `tables/cluster_selection_comparison.md`,
with one row for each successfully trained cluster-count candidate. It reads
training metrics and `training_time_seconds` from saved candidate metadata;
metric winners are ranked at full precision within each equivalent model
configuration, and ties are all bolded.

## Spectral co-clustering

To run the unconstrained scikit-learn `SpectralCoclustering` model, point the
model name in `models.run` in `config/default.yml`. The corresponding
configuration is loaded automatically from `config/models/<model_name>.yml`:

```yaml
models:
  run:
    - constrained_kmeans
    - spectral_coclustering
```

Only models listed in `models.run` are executed, in that order. Keep each
model's parameters and search settings in its matching
`config/models/<model_name>.yml` file. The spectral model configuration
supports fixed or automatic selection:

```yaml
name: spectral_coclustering
parameters:
  random_state: 12345
  n_init: 10
cluster_search:
  enabled: true
  candidates: [5, 6, 7]
  selected_n_clusters: auto
```

Set `selected_n_clusters` to a candidate integer (for example `5`) to use a
fixed count. Spectral co-clustering has no minimum-cluster-size constraint;
constraint applicability is saved as `not applicable`. Its `n_init` and
`random_state` parameters are passed to scikit-learn; `max_iter` is not
accepted because `SpectralCoclustering` does not expose that parameter.

The shared, training-fitted preprocessing remains unchanged. The model then
fits its own training-only min/max conversion to finite nonnegative values,
removes constant/all-zero feature columns from the spectral fit, and stores
that preprocessing with each candidate. All-zero training rows are omitted
from the spectral fit and assigned to the largest fitted row cluster;
all-zero future rows use the same deterministic rule. Saved active column
labels retain scikit-learn's zero-based labels; dropped feature columns use
`-1` in `column_labels.parquet`.

The registered `constrained_coclustering` and
`robust_constrained_coclustering` entries remain unimplemented templates;
selecting either currently raises `NotImplementedError`.

Because `SpectralCoclustering` has no `predict`, future customers are assigned
to the nearest centroid of the fitted row memberships in the model's saved,
nonnegative feature space. The model and `column_labels.parquet` are saved
separately per candidate. For fair customer-cluster comparisons, silhouette,
Davies–Bouldin, and Calinski–Harabasz are calculated in the shared fitted
preprocessing output space, not the model-specific nonnegative space.
Candidates that exceed the active matrix dimensions or otherwise cannot be
fit are reported as failed and are ineligible for automatic selection.
AP/F1 remain unavailable because this workflow has no ground-truth customer
class labels.

`constrained_coclustering` and `robust_constrained_coclustering` remain
configuration-only templates: their `fit()` and `predict()` methods explicitly
raise `NotImplementedError`.

## Robust Gaussian co-clustering

Add `robust_coclustering` to `models.run` in the central configuration. The
loader automatically reads `config/models/robust_coclustering.yml`. For example:

```yaml
models:
  run:
    - constrained_kmeans
    - kmeans
    - spectral_coclustering
    - robust_coclustering
```

Run through the normal CLI, `python -m cluster_representation --config
config/default.yml`, after editing the model list. `kmeans` is the unconstrained
scikit-learn baseline and uses `config/models/kmeans.yml`.

`models/robust_coclustering.py` is a thin adapter around the original
`models/robcoclust_constrained.py:tbcem_constrained`. The original algorithm source
is preserved byte-for-byte. The pipeline passes the shared training-fitted median
imputation and optional standard scaling output as a two-dimensional matrix.
The implementation treats each customer-feature cell as univariate (`d=1`). It
accepts signed values, so no nonnegative transform or feature removal is used.
The common clustering metrics use that same shared feature space. The core
algorithm also supports three-way arrays and missing cells; the pipeline uses
its existing two-dimensional, median-imputed representation.

The adapter passes the actual algorithm parameters through with their original
names and defaults. `g` counts row/customer clusters and `m` counts column/feature
clusters. With cluster search enabled, omit `g`: each candidate supplies `g`,
while `m` and every other parameter remain fixed. Automatic selection uses the
existing average ranks of silhouette, Davies--Bouldin and Calinski--Harabasz,
with smaller `g` breaking ties. For fixed fitting, remove `cluster_search` and
set `g` in `parameters`, or disable search and set a matching integer
`selected_n_clusters`. Search candidates must be at least two for metric-based
selection; direct fixed fitting also permits `g=1`, whose clustering metrics
are unavailable.

Parameters exposed in the robust model YAML:

| Parameter | Meaning |
|---|---|
| `g`, `m` | Separate row and column cluster counts |
| `row_size_min`, `row_size_max` | Training row-group size bounds; null defaults to 1 and training row count |
| `col_size_min`, `col_size_max` | Training column-group size bounds; null defaults to 1 and feature count |
| `trim_lvl` | Fraction of observed cells trimmed, default 0.10 |
| `c` | Global covariance eigenvalue-ratio bound, null disables it |
| `consistency` | Trimmed covariance consistency correction, default true |
| `n_init` | Requested random initialisations, default 10 |
| `until_converged` | Continue initialisations until a non-degenerate run, subject to the cap |
| `iter_max`, `tol` | Iteration cap and relative objective tolerance |
| `max_init` | Total initialisation cap; null uses ten times `n_init` |
| `max_init_attempts` | Random partition attempts per initialisation, default 50 |
| `init_max_cells` | Robust initial-estimation subsample per block, default 500; null uses all cells |
| `seed` | NumPy generator seed; null permits nondeterminism |
| `verbose` | Algorithm progress-print frequency or false |

Row and column size bounds are enforced by the original min-cost-flow solver.
Row minimum/maximum bounds feed pipeline violation checks. Column counts and
bounds are recorded in model metadata. Infeasible candidate fits and unavailable
metrics retain the existing failure/status schema. The algorithm retains its
own degeneracy fallback and warnings. Random partitions and subsampling use
`seed`; multivariate MCD initialization in the original source fixes its own
`random_state=0`. Dependencies include SciPy, scikit-learn, NumPy and OR-Tools,
now declared explicitly where needed.

The user-approved out-of-sample method exists only in the adapter. It keeps
training `w`, `mu`, `sigma` and `pi` fixed, initializes each row by maximum
posterior, then alternates the original Mahalanobis trimming and Gaussian row
posterior helpers until labels and mask stabilize. No model fitting or parameter
updates occur on test rows. Failure to stabilize within `iter_max` raises an
explicit error. No training size bounds apply to prediction batches. Trimming
uses the whole prediction batch, so batch composition can affect assignments.
An entirely masked row follows the fitted row proportions; ties use the lowest
cluster index. Pipeline input validation and train-fitted imputation handle
missing values before assignment.

Training one-hot memberships are validated before converting their indices to
one-based pipeline labels. Original `z`, `w`, `mu`, `sigma`, `pi`, `rho`, `mask`,
score, convergence summaries and all per-initialisation `evolution` histories
remain in `model.result_` in the joblib artifact. These histories can be large.
Reload through the existing `ClusterModel.load` or storage workflow. Training
IDs and feature order remain in stage metadata; column label Parquet artifacts
also contain feature names and indices. Separate model representation metadata
is saved beside each fitted model.

Column clustering affects the Gaussian model and prediction. Downstream
replacement uses the existing training-derived per-row-cluster feature medians,
independently of Gaussian block means. All configured NC scenarios reuse the
shared data split and indicators. Structured metrics, cluster-selection,
overall and feature tables, and their journal LaTeX exports include the model.
The overall table retains `N MAE` and omits raw MAE; raw MAE remains in structured
and feature results.
